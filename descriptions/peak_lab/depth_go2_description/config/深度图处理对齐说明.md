# 深度图处理与训练/Onboard 对齐说明

本文档对比**训练**（legged_robot.py）、**Onboard**（visual_extreme_parkour.py）与 **C++ 控制器**（StateRL::preprocessDepthImage）的深度图预处理，说明是否一致、差异在哪、如何检查。

---

## 一、整体流程对比

| 步骤 | 训练 (legged_robot.py) | Onboard (visual_extreme_parkour.py) | C++ (StateRL) |
|------|------------------------|-------------------------------------|---------------|
| 1. 裁剪 | `crop_depth_image`: `[:-2, 4:-4]`（去底 2、左 4、右 4） | `cropping[top:-bottom-1, left:-right-1]`，由参数指定 | `depth_crop_top/bottom/left/right`，由 config 指定 |
| 2. 数值范围 | clip 到 `[-far_clip, -near_clip]`（仿真深度为负），near=0, far=2 | clip 到 `[0, depth_range[1]]`（mm），再 `/ (range[1]-range[0])` → [0,1] | clip 到 `[0, max_depth]` |
| 3. 缩放 | **torchvision Resize((58,87), BICUBIC)**，先 resize | **F.adaptive_avg_pool2d** 到 (58,87)，在归一化后 | **cv::resize(..., INTER_CUBIC)** 到 (58,87)，与训练一致 |
| 4. 归一化到输入范围 | resize 后：`* -1` 再 `(x-near)/(far-near) - 0.5` → **[-0.5, 0.5]** | 先 `/ range` 得 [0,1]，resize 后 **-= 0.5** → **[-0.5, 0.5]** | **resize 后** `depth/max_depth - 0.5` → **[-0.5, 0.5]**，与训练顺序一致 |

结论：**C++ 已与训练完全一致**（BICUBIC + 先 resize 再归一化）。Onboard 仍为 adaptive_avg_pool2d + 先归一化再 resize。

---

## 二、一致的部分

- **远裁剪**：训练 `far_clip=2`，C++ `max_depth=2.0`，Onboard 可配为 2 m，一致。
- **近裁剪**：训练 near_clip=0，C++ 等价为 [0, max_depth]，一致。
- **输出范围**：三者均为 **[-0.5, 0.5]**。
- **输出尺寸**：训练/Onboard 均为 (H=58, W=87)；C++ 由 `depth_height=58`, `depth_width=87` 控制，一致。

---

## 三、差异与注意点

### 1. C++ 已与训练一致（当前实现）

- **Resize**：C++ 使用 **cv::INTER_CUBIC**，与训练 `torchvision.Resize(..., BICUBIC)` 一致。
- **顺序**：C++ 为 clip → **resize** → **normalize**（`depth/max_depth - 0.5`），与训练一致。

### 2. Onboard 与训练/C++ 的差异

- **Onboard** 仍使用 `F.adaptive_avg_pool2d`，且为先归一化再 resize，与训练不同；若需与 C++/训练完全一致，需改 Onboard 预处理。

### 3. 裁剪像素数

- **训练**：固定 `[:-2, 4:-4]`（针对仿真渲染分辨率）。
- **C++**：`depth_crop_top/bottom/left/right`（如 60, 100, 80, 36）需按**当前相机分辨率**设置，使裁掉边缘后的视野与训练/Onboard 尽量一致。不同分辨率下应使用不同 crop 值。

---

## 四、如何检查“手法是否一样”

1. **配置对齐**  
   - 确认 `max_depth=2.0` 与训练 `far_clip=2`、Onboard 的 depth_range 一致。  
   - 确认 `depth_height=58`, `depth_width=87` 与训练 `depth.resized=(87,58)`、Onboard `output_resolution=[58,87]` 一致。

2. **数值范围检查**  
   - 控制器已发布预处理后的深度图到 `/depth_image/processed`（若启用）。  
   - 用 `ros2 run rqt_image_view rqt_image_view` 或脚本读该话题，检查像素值是否大致在 **[-0.5, 0.5]**（若显示时做了线性映射，则看相对分布即可）。

3. **与 Onboard 对比（可选）**  
   - Onboard 发布的是已归一化、已 -0.5 的深度；若 C++ 订阅的是同一相机原始深度并自行预处理，可对比同一帧在 Onboard 与 C++ 下 `/depth_image/processed` 的差异，应主要来自 resize 方式（BICUBIC vs 平均池化）和 crop 像素数是否一致。

---

## 五、小结

| 项目 | C++ 与训练 | 说明 |
|------|------------|------|
| 裁剪思路 | 一致 | 都是去掉四边，C++ 用 config 像素数 |
| 远近裁剪范围 | 一致 | [0, 2] m，输出 [-0.5, 0.5] |
| Resize 方式 | 一致 | C++ 使用 cv::INTER_CUBIC，与训练 BICUBIC 一致 |
| 归一化与 resize 顺序 | 一致 | C++ 先 resize 再 depth/max_depth - 0.5 |
| 输出尺寸与范围 | 一致 | (58, 87)，[-0.5, 0.5] |

**C++ 深度预处理已与训练完全一致**。  
（若仍使用仓库里 Extreme-Parkour-Onboard 的 **Python 预处理管线**（如 visual_extreme_parkour.py），其与训练不一致；当前部署以 C++ 为准即可，无需改 Onboard。）
